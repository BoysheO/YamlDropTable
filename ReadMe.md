# YamlDropTable设计

## 概念
| 名字    | 说明                                                          |
| ----- | ----------------------------------------------------------- |
| 掉落 id | 代表一个道具 id 或另一个掉落池 id。`0` 固定表示空掉落。                           |
| 掉落数量  | 代表一次掉落的数量。既可以表达为固定数量，也可以表达为范围值。为了便于配置，数量为 `0`时，视作数量1处理。负数表示本次为空掉落。 |
| 权重    | 代表一个掉落 id 被抽中的权重，用整数表示。允许权重为 `0`，权重为 `0` 表示该项不会被抽中。权重不能为负数。 |
| 掉落池   | 代表一组掉落项。抽奖一次，掉落池只能从自身掉落项中抽出一种道具或空掉落。                          |
| 掉落表   | 代表一组掉落池。                        |
## 掉落 id 格式
掉落 id 为整型数字或道具名

## 掉落数量格式
掉落数量使用 `count_` 字段表达。

- ⚠ 掉落数量为0时，应视作掉落数量为1
- 数量为负数时，表示空掉落
- 缺省时，视作数量1

|模式|表达示例|
|--|--|
|固定数量|`count_: 1` `count_:0`|
|范围数量|`count_: [2, 4]`|
|空掉落|`count_: -1`|

## 权重规则
权重使用 `weight` 字段表达。
```yaml
weight: 100
```
规则如下：

| 规则                 | 说明           |
| ------------------ | ------------ |
| 权重必须是整数            | 不允许小数        |
| 权重不能为负数            | 例如 `-1` 非法   |
| 权重可以为 `0`          | 表示该项不会被抽中    |
| 权重为 `0` 的项可以保留在配置中 | 常用于临时关闭某个掉落项 |

注意区分：

| 配置          | 含义                        |
| ----------- | ------------------------- |
| `weight: 0` | 没有概率发生                    |
| `drop__: -1` | 有概率发生，发生后为空掉落             |
| `count_: -1` | 有概率发生，发生后为空掉落 |

## 掉落池表达格式
掉落池的命名，可以是中文，可以是英文。
掉落池类型有2种，一种是普通掉落池，一种是引用掉落池


```
⚠ 掉落池命名，不以特殊符号开始。
```

### 普通掉落池

普通掉落池使用 YAML 中的键值结构表达。
一个掉落池由多个掉落项组成。每个掉落项包含：
| 字段       | 必填 | 说明           |
| -------- | -- | ------------ |
| `weight` | 是  | 权重           |
| `drop__` | 是  | 掉落 id        |
| `count_` | 否  | 掉落数量，缺省为 `1` |

示例：

```yaml
#掉落池名字
装备池:
  - weight: 100
    drop__: 红缨枪
    count_: 1
  - weight: 50
    drop__: 飞镖
    count_: [2, 4]
  - weight: 20
    drop__: 0
```

该掉落池抽奖一次时，只会从上述掉落项中抽出一个结果。
```
⚠不允许定义空掉落池。空掉落池视作引用掉落池
```
### 引用掉落池
引用掉落池的意思是这个掉落池不在本处定义，在外部定义。
例如
```yaml
装备池:[]
```
或
```yaml
装备池:null
```
两种都是合法写法。表示使用外部定义（可能是定义在单独文件中的掉落池配置等）。
```
⚠ 实际处理引用池时，如果找不到对应的外部定义，应视作异常，不应静默处理处理，否则会难以查找配置失误问题
```
## 掉落表表达格式
掉落表使用 YAML 格式表达，根节点为 `groups`。
`groups` 下的每一个键代表一个掉落池名。

示例：
```yaml
groups:
  装备池:
    - weight: 100
      drop__: 红缨枪
      count_: 1
    - weight: 50
      drop__: 飞镖
      count_: [2, 4]
    #有20权重抽到空掉落
    - weight: 20
      drop__: 0
  材料与消耗品池:
    - weight: 80
      drop__: 药水
      count_: 1
    - weight: 40
      drop__: 高级药水
      count_: [1, 3]
    - weight: 10
      drop__: 大师药水
      count_: 1
    - weight: 70
      drop__: 0
  货币池:
    - weight: 100
      drop__: 铜币
      count_: 5
    - weight: 30
      drop__: 银币
      count_: 1
    - weight: 0
      drop__: 金币
      count_: 1
  任务道具池:null
```
抽奖一次时：
1. `装备池` 抽出一个结果；
2. `材料与消耗品池` 抽出一个结果；
3. `货币池` 抽出一个结果。
4. 查找`任务道具池`的定义，如果找到，则从中抽出一个结果
因此，该掉落表一次结算会执行所有掉落池。每个掉落池产生一个结果。如果某个掉落池抽中 `drop__: 0`，则该组本次为空掉落。

## 抽取办法
对空掉落项的处理模式

| 模式      | 规则描述                                     | 
| ------- | ---------------------------------------- | 
|允许空掉落| 有概率抽到空掉落||
|不允许空掉落|空掉落项的权重，视作0，即不会随机到空掉落|

| 模式      | 规则描述                                     | 行为说明                      |
| ------- | ---------------------------------------- | ------------------------- |
| 从掉落表抽取 1 个  | 先从掉落表中等权重抽取 1 个掉落池，再从该掉落池中抽取 1 个道具       | 只产生1个道具掉落 |
| 从掉落表抽取n个道具  | 取掉落表中的掉落池数量作为 n，每个掉落池贡献 1 个抽取结果          | 每个掉落池各执行 1 次抽奖，总道具数 = 池数量 - 空掉落次数 |
| 其它抽取逻辑 | 重复执行“掉落 1 个”的逻辑直到满足目标数量；或按配置动态分配各掉落池抽奖次数等等 | 可灵活调用定义的数据       |

## Q&A
- 为什么字段命名使用_符号结尾
  - 这是为了对齐上下条目，在数据量较大的情况下，仍能保持整齐布局
- 掉落数量为0时为什么要视作1
  - 这是为了防止程序上的默认值0混入造成语义分歧。作为策划语言来看，默认值为1是个合理的设计。
